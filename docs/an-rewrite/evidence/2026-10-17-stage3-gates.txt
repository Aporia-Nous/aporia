=== 14. why §7 (protocol check:generated) exits 1: line endings only, not stale content ===

(`git ls-files --eol` -> i/lf w/crlf). `generate-openapi.ts --check` compares bytes with its LF output, so it
fails on any CRLF checkout. Proof, run right after the gates at 45bfcbc516:
  bun run generate                      (rewrites openapi.json with LF)
  git diff --exit-code --quiet -- openapi.json               -> exit 0 (no content difference)
  git diff --ignore-cr-at-eol --exit-code --quiet -- openapi.json -> exit 0
  git diff --quiet (whole tree, incl. regenerated client)    -> exit 0
  git checkout -- packages/protocol/openapi.json packages/client/src   (restore CRLF working copies; tree clean)
The client check (§8) uses `git diff`, which normalises line endings, and passes.
